<article class="article" id="ja2"><h2>2. AIエージェントの権限設計はプロンプトより先に決める</h2><div class="meta"><span>専門</span><span>AIオリジナル学習記事</span><span>1326 字</span><span>Core</span></div><ul><li><a href="https://www.nist.gov/itl/ai-risk-management-framework" target="_blank" rel="noopener">NIST AI RMF</a></li></ul><section><h3>本文</h3><div class="bi"><div data-lang="ja"><h4>日本語</h4><p>AIエージェントの設計では、どのモデルを使うか、どのプロンプトを書くかが注目されやすい。しかし、実務で最初に決めるべきなのは権限である。文章を提案するだけのAIと、メール送信、データ更新、返金、発注などを実行できるAIでは、失敗したときの影響がまったく異なる。能力の高さより先に、何を許可し、何を禁止し、どこで人の承認を必要とするかを定義する必要がある。</p><p>権限は一段階ではなく、読み取り、下書き、実行、高リスク実行のように分けると整理しやすい。例えば、顧客情報を読むことはできても変更はできない、メール案を作成できても送信は人が行う、といった設計である。実行権限を与える場合も、すべての操作を同じ扱いにする必要はない。</p><p>金額閾値は典型的な方法である。少額返金は自動処理できても、高額返金は人の承認を求める。割引率、発注金額、契約期間なども同じ考え方で制御できる。これにより、「人が監督する」という抽象的な方針を、具体的な業務ルールへ変えられる。</p><p>ログも重要である。エージェントがどの情報を読み、どの指示を受け、どのツールを呼び出し、どの結果を得て、最終的に何を実行したかを追跡できなければ、事故調査は難しい。ログは開発者だけのものではない。監査、セキュリティ、顧客対応、品質改善にも必要である。</p><p>さらに、エージェントが誰の指示を優先するかも設計しなければならない。ユーザーの入力、社内文書、メール本文、外部サイトには、それぞれ異なる信頼度がある。文書中に書かれた命令をそのまま実行する設計では、意図しない操作や悪意ある指示に影響される可能性がある。指示元の権限を区別することは、ツール権限と同じくらい重要である。</p><p>停止条件も必要だ。情報が不足している、複数の指示が矛盾している、想定外の金額や顧客が出てきた場合、エージェントは無理に完了しようとせず、人へ引き継ぐべきである。安全なエージェントとは、何でもできるエージェントではなく、いつ止まるべきか理解しているエージェントである。</p><p>一方、承認を増やしすぎれば、自動化の価値が失われるという反論もある。これは正しい。すべての操作で人の確認を要求すれば、エージェントは単なる下書き支援になる。そこで、低リスクで取り消し可能な処理には高い自律性を与え、高影響で不可逆な処理には強い制約を置くという、リスクベースの設計が現実的である。</p><p>AIエージェントの導入で重要なのは、プロンプトを工夫する前に運用モデルを作ることだ。権限、閾値、ログ、指示元、停止条件、責任者を先に決めれば、後から能力を拡張しやすい。優れたプロンプトは行動を改善できるが、組織として「何をしてよいか」を決める代わりにはならない。</p><p>また、権限設計は一度決めて終わりではない。利用実績が増えると、最初は低リスクと考えていた処理でも、件数の増加によって累積影響が大きくなることがある。月次で実行件数、例外率、手動介入率、事故件数を確認し、閾値や承認ルールを見直す必要がある。自律性の拡大は、成功した実績と十分な監視データに基づいて段階的に行う方が安全である。</p><p>つまり、権限管理はセキュリティ機能だけではなく、AIエージェントを業務へ組み込むための経営設計でもある。</p></div><div data-lang="zh"><h4>繁中完整翻譯／解說</h4><p>AI Agent 設計時，大家常先討論模型與 prompt，但真正應先決定的是權限。只會產生文字的 AI，與能寄信、更新資料、退款或下單的 AI，失敗影響完全不同。能力愈強，愈需要先定義什麼可做、什麼禁止，以及哪裡必須人工批准。</p><p>權限最好分層，例如只讀、草稿、執行與高風險執行。可以允許讀客戶資料但不能修改，允許產生郵件草稿但由人寄出。即使有執行權，也不必所有操作一視同仁。</p><p>金額門檻是典型方法。小額退款可自動處理，大額退款需人工核准；折扣率、採購金額與合約期限也可用相同邏輯。如此能把抽象的「人類監督」變成具體工作規則。</p><p>Log 也很重要。若無法追蹤 Agent 看了什麼、接受什麼指令、呼叫什麼工具、得到什麼結果與最後執行什麼，就難以進行事故調查。Log 不只給開發者，也支援稽核、安全、客訴與品質改善。</p><p>此外，要定義 Agent 應聽誰的指令。使用者、內部文件、Email 與外部網站的可信度不同。如果把文件中的內容直接當成指令，可能遭遇惡意或意外的指令干擾。指令來源權限與工具權限同樣重要。</p><p>Agent 還需要停止條件。資訊不足、指令衝突、金額或客戶超出預期時，應停止並轉交人類，而不是硬要完成。安全的 Agent 不是什麼都能做，而是知道什麼時候不該繼續。</p><p>反方意見是核准太多會消滅自動化價值，這是正確的。因此實務上採風險導向自主：低風險、可逆操作給高自主，高影響且不可逆操作則加強限制。</p><p>權限設計也不是一次完成。使用量增加後，原本看似低風險的動作可能因規模放大而變得重要，所以應定期查看執行量、例外率、人工介入率與事故，逐步調整權限。</p><p>總之，AI Agent 導入應先建立 operating model：權限、門檻、log、指令來源、停止條件與責任人，之後再優化 prompt。好的 prompt 能改善行為，但無法取代組織對「什麼可以做」的治理設計。</p></div></div></section><section><h3>高階用語</h3><div class="article" id="ja3"><h2>3. 雑談で「正解」を返そうとしない方が会話が続く</h2><div class="meta"><span>N1</span><span>AIオリジナル学習記事</span><span>1305 字</span><span>Core</span></div><ul><li><a href="https://www.nhk.or.jp/bunken/" target="_blank" rel="noopener">NHK放送文化研究所</a></li></ul><section><h3>本文</h3><div class="bi"><div data-lang="ja"><h4>日本語</h4><p>雑談が苦手な人ほど、相手の話に「正しい答え」を返そうとすることがある。相手が「最近忙しくて」と言えば、時間管理の方法を提案し、「新しい店に行った」と言えば、おすすめの店を紹介する。親切な意図でも、相手が求めているのは解決策ではなく、単に気持ちや出来事を共有することかもしれない。</p><p>雑談では、問題解決より受け止めが先に来る。「それは大変ですね」「最近かなり忙しそうでしたよね」と短く返すだけで、相手は自分の話が届いたと感じやすい。その後で、相手が詳しく話し始めたら質問を一つ加える。逆に、返答が短ければ深追いしない。この順序が自然な会話を作る。</p><p>自己開示も役に立つ。相手が忙しさについて話したとき、「私も今週は予定が重なっていて、朝に整理しないと抜けそうです」と少しだけ自分の話を足すと、会話が一方向にならない。ただし、自分の話を長くしすぎると、相手の話題を奪ってしまう。雑談では完成した説明より、相手が入れる余白が重要である。</p><p>「正解」を返そうとすると、無意識に評価する姿勢になることもある。「それならこうした方がいいですよ」と言うと、相手は自分の選択を否定されたように感じる場合がある。特に仕事の雑談では、相手の状況を十分に知らないまま助言すると、距離ができることがある。求められていない助言は、正しくても会話には不要なことがある。</p><p>もちろん、助言そのものが悪いわけではない。相手が「どうしたらいいと思いますか」と聞いた場合や、具体的な情報を求めている場合には役に立つ。重要なのは、助言を出す前に相手の目的を読むことだ。「聞いてほしい」のか、「情報がほしい」のか、「一緒に考えてほしい」のかで返し方は変わる。</p><p>雑談を続けるコツは、話題を広げすぎないことでもある。相手の発言から一つだけ言葉を拾い、少し具体化する。「最近忙しい」に対して「月末だからですか」と一段だけ深める。二つ三つ質問を重ねず、相手の反応を待つ。そこで詳しく返ってくれば続け、短ければ別の話題へ移る。</p><p>反対に、沈黙を失敗と考えないことも大切だ。雑談は常に長く続く必要はない。「そうなんですね。お疲れさまです」で自然に終わる会話もある。無理に次の質問を探すより、相手が終えたいタイミングを尊重した方が、次回は話しやすくなる。</p><p>雑談力とは、面白い話題を大量に持つ能力でも、正しい助言をすぐ返す能力でもない。相手の言葉を受け止め、自分の情報を少し返し、反応に合わせて深さを調整する技術である。正解を急がない人ほど、相手が自分の言葉で話せる余地を作れる。その余地が、結果として会話と信頼を長くする。</p><p>職場では相手との関係性によっても適切な深さが変わる。初対面の相手には仕事、天気、移動、食事など比較的安全な話題から始め、反応を見ながら少しずつ個人的な話へ広げる方がよい。親しい同僚であっても、家族、健康、収入などは相手から話題に出した場合にだけ追う方が無難である。雑談の自然さは話題の豊富さより、境界線を読む力によって支えられている。</p><p>会話が短く終わっても関係が悪くなったとは限らない。相手が安心して終えられること自体が、次の会話につながる。それも重要な雑談力である。</p></div><div data-lang="zh"><h4>繁中完整翻譯／解說</h4><p>不擅長閒聊的人，常會努力對對方的話給出「正確答案」。對方說最近很忙，就立刻提供時間管理建議；對方說去了新店，就推薦其他店。即使出發點是好意，對方想要的可能不是解決方案，而只是分享近況與感受。</p><p>閒聊裡，先接住對方比解決問題更重要。「那真的很辛苦」「最近看起來確實很忙」這樣的短回應，就能讓對方感覺自己被理解。之後如果對方開始多講，再補一個問題；若回答很短，就不要追問。</p><p>適度自我揭露也有幫助。例如對方說很忙，可以回「我這週行程也有點擠，早上不整理就容易漏掉」。這能避免對話變成單向盤問，但自己的話也不能太長，因為閒聊需要讓對方有插入空間。</p><p>急著給「正解」有時也會形成評價姿態。「你應該這樣做」可能讓對方覺得自己的選擇被否定。尤其職場閒聊中，在不了解完整背景前給建議，反而可能拉開距離。未被要求的建議，即使正確，也不一定適合當下。</p><p>當然，對方明確問「你覺得怎麼辦」時，建議就有價值。關鍵是先判斷對方此刻需要被聽、需要資訊，還是需要一起思考。</p><p>另一個技巧是不要一次把話題拉太遠。從對方的一句話中挑一個詞，往下具體一層即可，例如「最近很忙」可以只問「是因為月底嗎？」然後等反應。對方多說就繼續，回答短就轉換話題。</p><p>沉默也不是失敗。很多閒聊自然結束在「這樣啊，辛苦了」。比起硬找下一個問題，尊重對方想結束的時點，反而讓下次更容易開口。</p><p>職場中還要依關係深度調整話題。初識者可從工作、天氣、交通、飲食等安全題目開始；家人、健康、收入等較私領域最好讓對方先主動提起。</p><p>所以，閒聊能力不是擁有大量有趣話題，也不是立刻給出正確建議，而是接住對方、適度分享自己、觀察反應並調整深度。越不急著給答案，越能留下讓對方用自己的話繼續說的空間。</p></div></div></section><section><h3>高階用語</h3><div
